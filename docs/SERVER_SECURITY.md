# راهنمای نصب سرور امن (`server/api.php`)

نسخه‌ی امن‌شده‌ی `api.php` داخل پوشه‌ی `server/` است. این راهنما می‌گوید چه چیزی عوض شده و چطور آن را روی هاست نصب کنید.

## چه چیزی درست شد

| مشکل در نسخه‌ی قبلی | وضعیت جدید |
|---|---|
| هیچ action ای احراز هویت نداشت؛ هر کسی با آدرس API می‌توانست همه‌ی داده‌ها را بخواند، فروش ثبت کند، سفارش حذف کند یا موجودی صندوق را تغییر دهد | ورود توکن صادر می‌کند و همه‌ی action ها به جز `login` توکن معتبر می‌خواهند. در غیر این صورت سرور **401** برمی‌گرداند |
| نقش مدیر ارشد از `requester_role` ارسالی اپ خوانده می‌شد و قابل جعل بود | نقش و دسترسی‌ها از دیتابیس و بر اساس توکن خوانده می‌شوند |
| دسترسی بخش‌ها (`buy` / `sell` / `inventory` / `accessories` / `analytics`) فقط در اپ چک می‌شد | سرور هم برای هر action دسترسی را چک می‌کند (**403**) |
| `admin_name` در لاگ‌ها از اپ گرفته می‌شد و قابل جعل بود | از نشست کاربر خوانده می‌شود |
| رمزها به‌صورت متن ساده ذخیره می‌شدند | با `password_hash` ذخیره می‌شوند. رمزهای قدیمی در اولین ورود موفق خودکار تبدیل می‌شوند |
| محدودیتی برای حدس زدن رمز نبود | بعد از ۵ تلاش ناموفق، ورود به مدت ۱۵ دقیقه مسدود می‌شود |
| **SQL Injection** در `update_registry_status` | با prepared statement رفع شد |
| رمز دیتابیس داخل `api.php` بود | به `config.php` منتقل شد (خارج از گیت) |
| پیام‌های خطای داخلی دیتابیس به کاربر نمایش داده می‌شد | پیام عمومی نمایش داده می‌شود و جزئیات در لاگ سرور ثبت می‌شود |
| `update_profile` و `logout` در سرور وجود نداشتند (دکمه‌ی ویرایش پروفایل کار نمی‌کرد) | اضافه شدند؛ هر کاربر فقط پروفایل خودش را ویرایش می‌کند و با تغییر رمز، نشست‌های دیگرش باطل می‌شوند |
| فروش هم‌زمان می‌توانست موجودی اکسسوری را منفی کند یا یک گوشی را دو بار بفروشد | به‌روزرسانی‌ها شرط موجودی و وضعیت دارند |
| در PHP 8.1 به بعد، مثلاً IMEI تکراری به جای پیام مناسب خطای 500 می‌داد | `mysqli_report(MYSQLI_REPORT_OFF)` رفتار مورد انتظار کد را برمی‌گرداند |

همه‌ی موارد بالا روی یک دیتابیس آزمایشی MariaDB تست شده‌اند. ساختار جدول‌های آن از روی کوئری‌های `api.php` بازسازی شده است، چون دیتابیس واقعی شما در دسترس نبود.

## مراحل نصب (به همین ترتیب)

> **ترتیب مهم است.** API جدید به همه‌ی درخواست‌های بدون توکن جواب 401 می‌دهد.
> APK های قدیمی توکن نمی‌فرستند و بعد از نصب سرور جدید فقط صفحه‌ی ورودشان کار می‌کند.
> پس **اول APK جدید را روی همه‌ی گوشی‌ها نصب کنید**، بعد سرور را عوض کنید.
> APK جدید با سرور قدیمی هم کار می‌کند.

1. **پشتیبان بگیرید:** از دیتابیس (phpMyAdmin → Export) و از فایل `api.php` فعلی.
2. **APK جدید را روی گوشی‌ها نصب کنید.**
3. **migration را اجرا کنید:** محتوای `server/migration.sql` را در تب SQL در phpMyAdmin اجرا کنید.
   این کار ستون `password` را به `VARCHAR(255)` تغییر می‌دهد و جدول‌های `admin_tokens` و `login_attempts` را می‌سازد.
4. **`config.php` بسازید:** از روی `server/config.example.php` فایلی به اسم `config.php` کنار `api.php` روی هاست بسازید و اطلاعات دیتابیس را داخلش بنویسید.
   این فایل نباید داخل گیت قرار بگیرد.
5. **آپلود کنید:** `server/api.php` و `server/.htaccess` را جای فایل‌های فعلی آپلود کنید.
   اگر هاست بعد از آپلود `.htaccess` خطای 500 داد، خط `CGIPassAuth On` را از آن پاک کنید. بعضی هاست‌ها این دستور را نمی‌شناسند. اپ توکن را با هدر `X-Auth-Token` هم می‌فرستد، پس بدون آن خط هم کار می‌کند.
6. **تست کنید:** با `admin1` وارد شوید و همه‌ی بخش‌ها را باز کنید.
7. **رمزها را عوض کنید.** رمز `admin1` (`123456`) داخل APK های قدیمی نوشته شده بود و عمومی است.
   از منوی کناری → ویرایش پروفایل، یک رمز قوی (حداقل ۸ کاراکتر) بگذارید. بهتر است رمز دیتابیس را هم از پنل هاست عوض کنید و در `config.php` به‌روز کنید.

## نکات

- **انقضای نشست:** توکن‌ها ۳۰ روز اعتبار دارند (`TOKEN_TTL_DAYS`). بعد از آن کاربر دوباره رمز را وارد می‌کند.
- **دسترسی به اعلان‌ها:** `get_notifications` برای همه‌ی کاربران واردشده باز است، مثل قبل. اگر نمی‌خواهید کاربران بدون دسترسی `analytics` نام بدهکاران را ببینند، در `api.php` خط `requirePermission($me, 'analytics');` را به ابتدای آن اضافه کنید.
- **دسترسی مدیر ارشد:** `get_admins`، `create_admin`، `delete_admin`، `update_admin_permissions` و `get_logs` فقط برای `super_admin` است.
- **حذف دسترسی یک کاربر:** حذف یک همکار، همه‌ی نشست‌هایش را هم باطل می‌کند.

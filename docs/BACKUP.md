# پشتیبان‌گیری و بازگردانی اطلاعات

همه‌ی اطلاعات مغازه، یعنی فروش‌ها، انبار، بدهی‌ها، هزینه‌ها و همکاران، در یک دیتابیس روی هاست نگه داشته می‌شود. دو روش پشتیبان‌گیری وجود دارد. بهتر است هر دو فعال باشند.

| روش | کجا ذخیره می‌شود | در برابر چه چیزی محافظت می‌کند |
|---|---|---|
| پشتیبان خودکار روزانه (Cron Job) | روی خود هاست، ۱۴ نسخه‌ی آخر | پاک شدن اشتباهی اطلاعات، خراب شدن دیتابیس |
| دکمه‌ی پشتیبان در اپ | روی گوشی یا تلگرام شما | از دست رفتن کامل هاست |

فایل پشتیبان یک فایل `.sql.gz` است: نسخه‌ی کامل و فشرده‌ی دیتابیس که مستقیم در phpMyAdmin قابل بازگردانی است.

> فایل پشتیبان شامل همه‌ی اطلاعات مالی، نام و شماره‌ی مشتری‌ها و رمزهای هش‌شده‌ی همکاران است.
> آن را فقط در جای امن (مثلاً Saved Messages تلگرام خودتان) نگه دارید و برای کسی نفرستید.

## فایل‌های سرور

این فایل‌ها کنار `api.php` آپلود می‌شوند:

- `backup_lib.php`: منطق مشترک تهیه‌ی پشتیبان (دسترسی مستقیم به آن با `.htaccess` بسته است)
- `backup_cron.php`: اسکریپت پشتیبان خودکار
- `api.php` و `.htaccess`: نسخه‌ی جدید

## ۱. دکمه‌ی پشتیبان در اپ

فقط برای **مدیر کل**: منوی کناری → «پشتیبان‌گیری از اطلاعات» → «تهیه و ارسال نسخه‌ی پشتیبان».

منوی اشتراک‌گذاری گوشی باز می‌شود و فایل را می‌توانید به تلگرام، ایمیل یا هر جای دیگر بفرستید. همین صفحه زمان آخرین پشتیبان خودکار سرور را هم نشان می‌دهد.

## ۲. پشتیبان خودکار روزانه (Cron Job)

در پنل هاست (cPanel یا DirectAdmin) بخش **Cron Jobs** را باز کنید و یک Cron Job جدید بسازید:

- **زمان:** هر روز ساعت ۳ بامداد. در cPanel تنظیم «Once Per Day» یا مقادیر `0 3 * * *`
- **دستور:**

```
php /home/USERNAME/public_html/backup_cron.php
```

`USERNAME` و مسیر را با مسیر واقعی `api.php` روی هاست خود جایگزین کنید. مسیر کامل معمولاً در File Manager بالای صفحه نوشته شده است.

پشتیبان‌ها در پوشه‌ی `backups` کنار همین فایل ذخیره می‌شوند. این پوشه خودکار ساخته می‌شود و دسترسی از اینترنت به آن بسته است. فقط ۱۴ نسخه‌ی آخر نگه داشته می‌شود.

### تنظیمات اختیاری در `config.php`

```php
'backup_dir'  => '/home/USERNAME/promax-backups',  // بهتر: پوشه‌ای بیرون از public_html
'backup_keep' => 14,                                // تعداد نسخه‌های نگه‌داشته‌شده
```

### اگر هاست فقط Cron با آدرس اینترنتی را پشتیبانی می‌کند

یک کلید تصادفی حداقل ۱۶ کاراکتری در `config.php` بگذارید:

```php
'backup_cron_key' => 'یک-رشته‌ی-تصادفی-طولانی',
```

و دستور Cron را این‌طور بنویسید:

```
wget -q -O /dev/null "https://promaxmobile.ir/backup_cron.php?key=یک-رشته‌ی-تصادفی-طولانی"
```

بدون این کلید، اجرای `backup_cron.php` از طریق اینترنت ممنوع است (403).

### بررسی

بعد از اولین اجرا، در اپ صفحه‌ی «پشتیبان‌گیری از اطلاعات» زمان آخرین پشتیبان را نشان می‌دهد.
برای اجرای فوری و دیدن نتیجه، در Terminal هاست (اگر دارید) همان دستور Cron را اجرا کنید. خروجی موفق شبیه این است:

```
ok: promax-backup-2026-11-25_0300.sql.gz (48.2 KB), kept 1 backups
```

## ۳. بازگردانی

> بازگردانی همه‌ی اطلاعات فعلی دیتابیس را با محتوای فایل پشتیبان **جایگزین** می‌کند.
> اگر دیتابیس فعلی هنوز در دسترس است، قبل از بازگردانی یک پشتیبان تازه از آن بگیرید.

1. phpMyAdmin را باز کنید و از ستون سمت چپ دیتابیس اپ را انتخاب کنید.
2. تب **Import** را باز کنید.
3. فایل `.sql.gz` را انتخاب کنید. لازم نیست آن را از حالت فشرده خارج کنید.
4. **Go** (یا **Import**) را بزنید.

بعد از بازگردانی، همه‌ی کاربران باید دوباره وارد اپ شوند، چون نشست‌ها در پشتیبان ذخیره نمی‌شوند.
